# Android 실기기 테스트 체크리스트

이 원격 개발 환경엔 Android SDK가 없어 아래 항목은 전부 **미검증** 상태다. 로컬 Android Studio에서
`docs/ANDROID_SETUP.md` 절차대로 앱을 설치한 뒤, 이 문서를 채워가며 진행한다. **이 체크리스트가 통과되기
전에는 PR #4를 "Android 기능 완료"로 간주하지 않는다** (`docs/PRODUCT.md`/PR 설명 참고).

## 공통 테스트 환경 (한 번만 기록)

| 항목 | 값 |
|---|---|
| 기기 모델 | |
| Android 버전 | |
| 앱 버전/커밋 해시 | |
| `server.url`이 가리키는 배포(프리뷰/프로덕션) | |
| 테스트 날짜 | |

각 시나리오는 아래 표의 열을 채운다: **재현 절차 / 기대 결과 / 실제 결과 / 통과 여부 / 관련 로그**.
개별 시나리오가 공통 환경과 다른 조건(특정 Android 버전 등)이 필요하면 시나리오 행에 따로 표기한다.

## 3. 알림 상태(기기 상태별)

| # | 시나리오 | 재현 절차 | 기대 결과 | 실제 결과 | 통과 | 로그 |
|---|---|---|---|---|---|---|
| 3.1 | 앱이 열린 상태 | 앱 포그라운드에서 예약 시각 도달 | 알림 표시, 탭하면 즉시 반영 | | ☐ | |
| 3.2 | 백그라운드 상태 | 앱을 백그라운드로 보낸 채 대기 | 알림 도착, 액션 탭 시 정상 반영(화면 노출 여부 기록) | | ☐ | |
| 3.3 | 최근 앱 목록에서 제거 | 앱 스와이프 종료 후 대기 | 알림 여전히 도착·처리됨(콜드 스타트) | | ☐ | |
| 3.4 | 화면 잠금 상태 | 기기 잠금 후 대기 | 알림 표시, 액션 탭 시 처리(잠금 해제 필요 여부 기록) | | ☐ | |
| 3.5 | 절전 모드(Doze) | 장시간 미사용 후 절전 진입, 예약 시각 도달 대기 | 알림 도착(지연 정도 기록) | | ☐ | |
| 3.6 | 휴대전화 재부팅 후 | 재부팅 → 앱 안 연 상태로 대기 | 알림이 살아있는지(`RECEIVE_BOOT_COMPLETED` 권한 확인), 안 살아있으면 다음 앱 실행 시 `reconcile()`로 복구되는지 | | ☐ | |
| 3.7 | 네트워크 연결 상태 | 정상 네트워크에서 액션 탭 | 즉시 서버 반영 | | ☐ | |
| 3.8 | 네트워크 차단 상태 | 기내 모드로 액션 탭 → 네트워크 복구 | 탭이 로컬 큐에 보존됨, 복구 후(앱 재개 시) 자동 반영 | | ☐ | |

## 4. 액션

| # | 시나리오 | 재현 절차 | 기대 결과 | 실제 결과 | 통과 | 로그 |
|---|---|---|---|---|---|---|
| 4.1 | 시작 | 알림에서 "시작" 탭 | GoalExecution `started`로 반영 | | ☐ | |
| 4.2 | 5분 미루기 | "5분 미루기" 탭 | `snoozed` 반영, 약 5분 뒤 두 번째 알림 도착(정확히 5분은 아닐 수 있음 — 오차 기록) | | ☐ | |
| 4.3 | 연속 미루기 | 스누즈 알림에서 다시 미루기 반복 | `snoozeCount` 증가, 매번 새 스누즈 알림 | | ☐ | |
| 4.4 | 최대 미루기 횟수 도달 | `maxSnoozeCount`만큼 미루기 반복 | 이후 미루기 요청은 `SNOOZE_LIMIT_REACHED`로 거부, 앱에서 미루기 버튼 숨김 | | ☐ | |
| 4.5 | 오늘 건너뛰기 | "오늘 건너뛰기" 탭 | `skipped` 반영(터미널 상태 — 되돌릴 수 없음, 실수 탭 위험 기록) | | ☐ | |
| 4.6 | 완료 | 인앱 모달에서 완료 처리 | `completed` 반영 + 애니메이션 | | ☐ | |
| 4.7 | 동일 액션 연속 누르기 | 같은 알림 액션 두 번 빠르게 탭 | 중복 반영 없음(멱등), history에 중복 기록 없음 | | ☐ | |
| 4.8 | 오래된 알림 액션 | 목표 시각 변경 전 알림을 보존해뒀다가 변경 후 탭 | `scheduleVersion` 불일치로 거부, "이전 일정" 배너 표시, GoalExecution 안 바뀜 | | ☐ | |
| 4.9 | 목표 시간 변경 후 이전 알림 액션 | 4.8과 동일 시나리오, 변경 전/후 흐름 전체 기록 | 새 시각으로 재예약됨 + 이전 알림은 무해하게 처리됨 | | ☐ | |

## 5. 데이터 검증

| # | 시나리오 | 재현 절차 | 기대 결과 | 실제 결과 | 통과 | 로그 |
|---|---|---|---|---|---|---|
| 5.1 | GoalExecution 중복 생성 없음 | 여러 경로(알림, 인앱)로 같은 날 액션 반복 | `occurrenceKey` 기준 레코드 1개만 존재 | | ☐ | |
| 5.2 | occurrenceKey 유지 | 목표 시각 변경 전후 실행 기록 비교 | 과거 기록의 `occurrenceKey`/`scheduledFor` 불변 | | ☐ | |
| 5.3 | snoozeCount 정상 증가 | 여러 번 미루기 | 매 미루기마다 정확히 1씩 증가 | | ☐ | |
| 5.4 | 종료 상태 재개방 없음 | `completed`/`skipped` 상태에서 알림 액션 재시도 | 409 또는 무시, 상태 안 바뀜 | | ☐ | |
| 5.5 | 테스트 데이터 통계 제외 | "지금 테스트" 버튼으로 만든 기록 확인 | `isTest:true`로 표시됨(실제 통계 로직 생기면 제외 대상) | | ☐ | |
| 5.6 | 앱 재실행 후 상태 복구 | 앱 종료 후 재실행 | 홈 화면이 서버의 최신 GoalExecution 상태를 정확히 반영 | | ☐ | |
| 5.7 | 서버 저장 실패 후 재시도 | 액션 탭 직후 네트워크 차단 → 복구 | 오프라인 큐가 재시도해 최종적으로 서버에 반영됨(3.8과 연계) | | ☐ | |
